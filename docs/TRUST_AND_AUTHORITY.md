# Trust and Authority Boundary

The Mesh distinguishes four different questions that must never collapse into one:

1. **Did I receive the advertised bytes?** — cryptographic/content verification.
2. **Who published or relayed them?** — provenance/authentication.
3. **Are they compatible with my consumer/runtime?** — compatibility verification.
4. **Should I professionally accept/use them?** — local + Profession Fabric evidence/governance decision.

A YES to one question is not a YES to the others.

## No reputation shortcut

Reputation may help prioritize discovery, but it cannot replace evidence. A highly trusted publisher can still be wrong; an unknown node can still relay byte-identical accepted content.

## No newest-wins rule

A newer version is a candidate, not an upgrade command. Nodes may pin older versions when continuity, compatibility, evidence, or user preference requires it.

## No silent convergence

The Mesh is allowed to remain plural. Different nodes may accept different package versions or status interpretations. Disagreement is preserved through version/digest/proposal history rather than resolved through forced network consensus.

## Proposal-back

A local node can propose improvements with:

- base package id/version/digest;
- proposed delta or replacement digest;
- evidence references;
- discovered failure/need;
- compatibility claims;
- explicit non-claims.

Upstream decides through its own roots/evidence process.
